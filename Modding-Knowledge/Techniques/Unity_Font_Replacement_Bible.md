# คัมภีร์: เทคนิคการสลับฟอนต์ (Font Replacement) ในเกม Unity

การสลับฟอนต์เป็นหัวใจสำคัญของการทำม็อดแปลภาษาไทย เนื่องจากฟอนต์ดั้งเดิมของเกมต่างประเทศมักไม่รองรับอักขระภาษาไทย คัมภีร์เล่มนี้รวบรวมเทคนิค 3 ระดับสำหรับการสลับฟอนต์ในเอนจิน Unity ตั้งแต่วิธีมาตรฐานไปจนถึงวิธีขั้นสูงสำหรับเกมที่ดื้อรั้น

---

## 🛠️ วิธีที่ 1: การเปลี่ยนฟอนต์แบบ Runtime (BepInEx / Harmony)
เป็นวิธีที่ "สะอาด" ที่สุด เนื่องจากไม่ต้องดัดแปลงไฟล์หลักของเกม แต่อาศัยการแทรกแซงการทำงานของเกมในขณะรัน (In-memory hooking)

**📌 เหมาะสำหรับ:** เกมส่วนใหญ่ที่ไม่ได้มีการบังคับล็อกฟอนต์อย่างเข้มงวด
**✅ ข้อดี:** ไม่ทำให้ไฟล์เกมพัง, ปลอดภัยเมื่อเกมอัปเดตแพตช์
**❌ ข้อเสีย:** อาจใช้ไม่ได้ผลกับเอนจิน Unity บางเวอร์ชัน (เช่น Freetype ปฏิเสธการเรนเดอร์) หรือเกมที่เขียนสคริปต์ทับฟอนต์เอง

**วิธีการ (C# Script):**
ใช้ Harmony Patch เข้าไปแทรกแซงคลาส UI ของ Unity เช่น `UnityEngine.UI.Text` หรือ `TMPro.TextMeshProUGUI`
```csharp
[HarmonyPatch(typeof(Text), "OnEnable")]
public class Text_OnEnable_Patch {
    static void Postfix(Text __instance) {
        // โหลดฟอนต์ภาษาไทยจากไฟล์ในเครื่อง
        Font thaiFont = Font.CreateDynamicFontFromOSFont("MyThaiFont", 24);
        __instance.font = thaiFont;
    }
}
```

## 🛠️ วิธีที่ 2: การฉีดและยัดไส้ไฟล์โดยตรง (Static Asset Injection & Padding)
หากวิธีที่ 1 ล้มเหลว (เช่น เกมแสดงผลตัวอักษรเป็นสี่เหลี่ยม หรือ Unity ปฏิเสธฟอนต์ใหม่) เราต้องใช้วิธี **"ผ่าตัด"** โดยการยัดไฟล์ฟอนต์ทับลงไปในไฟล์ทรัพยากรของเกม (เช่น `resources.assets` หรือ `sharedassets0.assets`)

**📌 เหมาะสำหรับ:** เกมที่แอนตี้การรันไทม์ม็อด หรือเอนจิน Unity เก่าๆ
**✅ ข้อดี:** ชัวร์เกือบ 100% ว่าเกมจะใช้ฟอนต์ของเราแน่ๆ
**❌ ข้อเสีย:** ต้องปรับแต่งไฟล์ขนาดใหญ่ และ **ขนาดไฟล์ฟอนต์ใหม่ห้ามใหญ่กว่าของเดิมเด็ดขาด**

**วิธีการ (Python + UnityPy):**
เนื่องจากเอนจิน Unity มีการอ้างอิง Byte Offset ที่รัดกุม หากเรายัดไฟล์ที่ขนาดไม่เท่าเดิมลงไป เกมจะเด้ง (Crash) ทันที เราจึงต้องใช้เทคนิค **Padding (ยัดไส้ด้วย Null Bytes)**
```python
import UnityPy

env = UnityPy.load("resources.assets")
with open("MyThaiFont.ttf", "rb") as f:
    custom_ttf = f.read()

for obj in env.objects:
    if obj.type.name == 'Font':
        data = obj.read()
        if data.m_Name == "OriginalGameFont":
            original_size = len(data.m_FontData)
            
            # เช็คว่าฟอนต์เราเล็กกว่าหรือเท่ากับของเดิมหรือไม่
            if len(custom_ttf) <= original_size:
                # เติม Null Bytes (\x00) ต่อท้ายจนกว่าจะเท่าขนาดเดิมเป๊ะๆ
                padded_ttf = custom_ttf.ljust(original_size, b'\x00')
                data.m_FontData = padded_ttf
                data.save()
```

## 🛠️ วิธีที่ 3: การทำอัมพาตสคริปต์เกม (Script Neutralization)
ในบางกรณี แม้เราจะทำตามวิธีที่ 1 หรือ 2 แล้ว แต่ปรากฏว่าฟอนต์ในเกมก็ยังไม่เปลี่ยน! อาการนี้มักเกิดจากตัวเกมมี **สคริปต์เฉพาะกิจ** ที่ผู้พัฒนาเขียนขึ้นมาเพื่อบังคับรีเซ็ตฟอนต์ทุกๆ เฟรม (เช่น คลาส `FontAttach` หรือ `LocalizationManager`)

**📌 เหมาะสำหรับ:** เกมที่ดื้อรั้นขั้นสุด (เช่น Harvest Moon: Light of Hope)
**✅ ข้อดี:** ทะลวงการป้องกันของโค้ดเกมได้เบ็ดเสร็จ
**❌ ข้อเสีย:** ต้องทำ Reverse Engineering (Decompile) โค้ดเกมเพื่อหาตัวการ

**วิธีการ:**
1. ใช้โปรแกรมเช่น **dnSpy** เพื่อแกะโค้ด `Assembly-CSharp.dll` 
2. ค้นหาคำว่า `Font` หรือ `text.font =` เพื่อหาสคริปต์ตัวการ
3. เขียน BepInEx Plugin เพื่อทำอัมพาตมันด้วย `Prefix` Patch ที่รีเทิร์น `false` ทันที

```csharp
// ตัวอย่างการปิดฟังก์ชันบังคับเปลี่ยนฟอนต์ของเกม
public static bool FontAttach_Update_Prefix() {
    // รีเทิร์น false เพื่อบอก Harmony ว่า "ไม่ต้องทำโค้ดต้นฉบับต่อแล้ว จบแค่นี้"
    return false; 
}
```

## ⚠️ บทสรุปและการจัดการภาษาไทย (PUA)
ไม่ว่าจะสลับฟอนต์ด้วยวิธีไหน ปัญหาที่หลีกเลี่ยงไม่ได้ใน Unity คือ **"สระจม/ลอย/เหลื่อมทับ"** 

**วิธีแก้ปัญหาภาษาไทยที่ยั่งยืนที่สุดคือ:**
1. ใช้ฟอนต์ที่จูนรหัส **PUA (Private Use Area)** มาแล้ว 
2. รันสคริปต์แปลงข้อความ (Text Converter) เพื่อเปลี่ยนรหัสสระ (เช่น `สระอี`) ไปใช้รหัสพิเศษในตำแหน่งที่ฟอนต์ PUA ถูกวาดหลบหางเอาไว้
3. แพ็กข้อความ PUA เหล่านั้นกลับเข้าเกม คู่กับการสลับฟอนต์ PUA เข้าไปในระบบ

จบหลักสูตรวิชาดัดแปลงฟอนต์ Unity ครับ!
