# 📖 คู่มือการแปลและรักษาโครงสร้างไฟล์ .lang (Minecraft/LANG Localization Bible)

คู่มือนี้สรุปโครงสร้างของไฟล์แปลภาษาประเภท `.lang` (ที่ใช้บ่อยใน Minecraft Bedrock Add-Ons และระบบเกมอินดี้ต่างๆ) และเทคนิคการรักษาโครงสร้างบรรทัด (Line-Based Structure Preservation) เพื่อช่วยให้คุณสามารถนำเข้า แปล และแพ็คไฟล์กลับ (Deploy) ได้ 100% โดยที่ไม่มีผลกระทบต่อโครงสร้างไฟล์ระบบดั้งเดิม

---

## 1. โครงสร้างของไฟล์ .lang
ปกติแล้วไฟล์ `.lang` จะเป็นไฟล์ข้อความแบบ Key-Value แยกด้วยเครื่องหมาย `=` และมีการใส่คอมเมนต์คำอธิบายและจัดบรรทัดเว้นว่าง ดังนี้:
```properties
pack.name=Wilderness Add-On
pack.description=Required resource pack for the Wilderness Add-On!

# addon messaging:
action.hint.exit.lb_wa:giraffe=Press sneak to exit
```
### ⚠️ ปัญหาทางเทคนิคที่มักพบในการแปล:
1.  **การสลับบรรทัด (Row Shift):** ถ้าดึงเฉพาะบรรทัดที่ต้องการแปลออกมาเขียนกลับเข้าไปใหม่ โครงสร้างบรรทัดอธิบาย (Comments) และบรรทัดเว้นว่างจะหายไปทั้งหมด ทำให้ผู้อื่นนำไปดัดแปลงต่อยาก
2.  **คีย์ซ้ำกัน (Duplicate Keys):** ในบาง Mod อาจมีการเรียกใช้คีย์เดิมซ้ำหลายๆ บรรทัด หากนำเข้าโดยใช้คีย์เป็น ID ตรงๆ ระบบจะยุบเหลือบรรทัดเดียว ส่งผลให้ข้อมูลบางส่วนสูญหายตอนแพ็คกลับ

---

## 2. วิธีการแก้ปัญหาของ TStudio (Line-Based Addressing & Metadata Cache)
เพื่อแก้ไขปัญหานี้อย่างถาวร TStudio ได้ใช้แนวทางประมวลผลผ่านตัวระบุบรรทัด (Line-based Unique ID) ดังนี้:

### ขั้นตอนที่ 1: การนำเข้าและสกัดโครงสร้าง (Import & Parsing)
เมื่อเปิดไฟล์ `.lang` ใน TStudio:
1.  โปรแกรมจะสร้างไฟล์สำรองโครงสร้างข้อมูลเดิมชื่อ `[ชื่อไฟล์]_tstudio_meta.json`
2.  บันทึกตำแหน่งบรรทัดว่างและคอมเมนต์ (ที่ขึ้นต้นด้วย `#`) ไว้ในไฟล์ JSON ดังกล่าว
3.  ในบรรทัดคำแปลจริง โปรแกรมจะสกัดมาเขียนลงไฟล์โปรเจกต์ CSV โดยใช้รูปแบบ ID เป็น:
    `L[เลขบรรทัด]_[ชื่อคีย์]` (เช่น `L4_action.hint.exit.lb_wa:red_necked_ostrich`)
    
*ตัวอย่างการแสดงผลในตาราง TStudio:*
- **ID:** `L4_action.hint.exit.lb_wa:red_necked_ostrich`
- **Source:** `Press sneak to exit`

### ขั้นตอนที่ 2: การอัปเดตสถิติและความคืบหน้า
ระบบประมวลผลสถิติแบบ $O(1)$ จะอ่านรหัสบรรทัดเฉพาะแถวที่คุณกำลังพิมพ์และอัปเดตสถิติทันที โดยไม่ต้องวนลูปประมวลผล Regex บนทุกบรรทัดใหม่ทั้งหมด ทำให้ไม่เกิดอาการพิมพ์หน่วงบนไฟล์ขนาดใหญ่

### ขั้นตอนที่ 3: การแพ็คกลับคืน (Deploy & Reconstruction)
เมื่อกดปุ่ม **"🚀 Deploy to Game"** หรือ **"Export Origin"**:
1.  โปรแกรมจะไปเปิดอ่านไฟล์โครงสร้าง `_meta.json` 
2.  วนลูปตามลำดับบรรทัดเดิมจาก 1 ถึง N:
    - หากเป็นคอมเมนต์หรือบรรทัดเว้นว่าง: เขียนข้อมูลดิบเดิมกลับลงไปที่บรรทัดนั้นทันที
    - หากเป็นบรรทัดคำแปล: มองหาคำแปลล่าสุดจาก CSV ด้วย ID `L{เลขบรรทัด}_{ชื่อคีย์}` หากแปลไว้จะดึงค่าแปลมาเขียน หากปล่อยว่างจะดึงข้อความภาษาอังกฤษดั้งเดิมมาใส่
3.  เขียนทับลงไฟล์ `.lang` เดิมอย่างสมบูรณ์แบบและเป็นระเบียบ

---

## 3. ขั้นตอนการใช้งานจริงใน TStudio
1.  เปิดโปรแกรม TStudio
2.  เลือกเมนู **File -> Open / Import File** และเลือกไฟล์ `.lang` (เช่น `en_US.lang`)
3.  โปรแกรมจะนำเข้าและแสดงพิกัดบรรทัดเดิมให้ในช่อง ID เช่น `L10_tile.lb_wa:walnut_log.name`
4.  พิมพ์ข้อความแปลภาษาไทย (หรือใช้ปุ่มแปลหลายบรรทัด AI)
5.  กด **File -> Save Project** เพื่อเซฟงานแปลลงไฟล์ CSV
6.  กด **File -> Deploy to Game** เพื่อทำการเขียนทับข้อความแปลกลับเข้าไปในไฟล์ `.lang` ตัวจริงได้ทันทีอย่างปลอดภัย!
