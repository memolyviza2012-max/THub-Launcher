# คัมภีร์การ Mod เกม Wasteland 3 (ภาษาไทย)

เอกสารฉบับนี้รวบรวมองค์ความรู้และเทคนิคที่ใช้ในการทำ Mod ภาษาไทยให้กับเกม **Wasteland 3** ซึ่งเป็นเกมที่พัฒนาด้วยเอนจิน **Unity (IL2CPP)** เอกสารนี้เน้นย้ำถึงขั้นตอนการสกัดข้อความ การนำกลับเข้าไปในเกม และที่สำคัญที่สุดคือ "เทคนิคการจัดการฟอนต์และการแสดงผลภาษาไทย (สระ/วรรณยุกต์)" ซึ่งจะเป็นบทเรียนล้ำค่าสำหรับการทำ Mod เกม Unity الاื่นๆ ในอนาคต

---

## 1. การจัดการข้อความ (Text Extraction & Injection)

Wasteland 3 ใช้ระบบการจัดการ Asset ผ่าน Addressables โดยไฟล์ข้อความหลักจะถูกรวมไว้ในไฟล์ Bundle
*   **ไฟล์เป้าหมาย:** `WL3_Data/StreamingAssets/aa/StandaloneWindows64/oei_assets_stringtabledata_english_e4607...bundle`
*   **โครงสร้างภายใน:** ข้อความทั้งหมดถูกเก็บเป็น Data Structure รูปแบบ `MonoBehaviour` ภายใต้ชื่อ `StringTableData_English`

### วิธีการสกัด (Unpack) และแพ็กกลับ (Pack)
เพื่อรักษาเสถียรภาพและทำงานร่วมกับ **THub (TStudio/TRun)** ได้อย่างเต็มรูปแบบ เราจึงเขียน Standalone Python Scripts โดยใช้ไลบรารี `UnityPy`:

1.  **Wasteland3_unpacker.py:** สกัดข้อความภาษาอังกฤษออกมาเป็นไฟล์ CSV มาตรฐาน TStudio (คอลัมน์: `ID`, `Source`, `Translation`, `AI_Reference` และเข้ารหัสแบบ `utf-8-sig`)
2.  **Wasteland3_packer.py:** นำไฟล์ CSV ที่แปลแล้ว แพ็กกลับเข้าไปในไฟล์ `.bundle` เดิม โดยก่อนแพ็ก **"ต้องผ่านการแปลงข้อความเป็น PUA (Private Use Area)"** ผ่าน `Core.tpua_engine` ของ Modder Hub เสมอ เพื่อแก้ปัญหาสระลอยเบื้องต้น

## 2. หัวใจสำคัญ: การทำภาษาไทยให้สมบูรณ์ (ฟอนต์และ PUA)

ปัญหาคลาสสิกของเกม Unity ที่ใช้ **TextMeshPro (TMP)** คือ ระบบไม่รองรับ Complex Text Shaping ทำให้สระบน/ล่าง และวรรณยุกต์ของภาษาไทยทับซ้อนกัน

### 2.1 การบังคับโหลดฟอนต์ภาษาไทยผ่าน C# IL2CPP Plugin
ตัวเกมเดิมไม่มีฟอนต์ภาษาไทยและถูกตัด (Strip) โค้ดส่วนเกินออก (IL2CPP) การจะยัดฟอนต์เข้าไปตรงๆ มักทำได้ยาก วิธีแก้ปัญหาที่ได้ผลที่สุดคือการเขียน **BepInEx IL2CPP Plugin**:
1.  ปลั๊กอินจะโหลดไฟล์ OS Font (ไฟล์ `.ttf`) ที่เตรียมไว้จากโฟลเดอร์ของ Mod
2.  นำไฟล์ `.ttf` มาสร้างเป็น `UnityEngine.Font` ใน Runtime
3.  แปลงเป็น `TMP_FontAsset` และนำไปยัดใส่ `TMP_Settings.fallbackFontAssets` เพื่อให้ Text ทุกตัวในเกมเรียกใช้ฟอนต์นี้อัตโนมัติหากหาตัวอักษรไม่เจอ

### 2.2 บทเรียนสำคัญ: ทำไมแค่ PUA ถึงยังไม่พอ? (การเลือกฟอนต์)
ในตอนแรก เราได้ทดสอบนำฟอนต์ **Kanit (Kanit-Regular_PUA.ttf)** มาใช้งานร่วมกับการแปลงข้อความ PUA ผลลัพธ์คือ เกมแสดงผลภาษาไทยได้ แต่วรรณยุกต์ที่อยู่ตำแหน่งสูง (เช่น คำว่า "เลือกระดับความยาก" ที่ไม้โท ต้องอยู่เหนือสระอือ) **เกิดการทับซ้อนและจัดช่องไฟผิดพลาด**

**สาเหตุ:** 
แม้ข้อความจะถูกแปลงเป็น PUA เพื่อแยก Character โค้ดของสระหลบ/สระลอยแล้ว แต่ **"ตัวไฟล์ฟอนต์เอง (Font file)"** อาจไม่ได้ถูกออกแบบมาให้มีการกำหนด Anchor หรือระยะห่าง (Metrics) ของสระและวรรณยุกต์ชั้นที่ 2 (Upper Mark) ไว้ให้เข้ากับเอนจินเกม

**การแก้ไขและการเลือกฟอนต์ (The Fix):**
เราเปลี่ยนมาใช้ฟอนต์ **`1_IBMPlexSans_fixByNodNuatTranslator_2.ttf`**
ฟอนต์นี้เป็นฟอนต์ที่ถูก **"ปรับแต่ง (Fix) ระยะ Anchor และความสูงของวรรณยุกต์มาโดยเฉพาะ สำหรับการทำ Mod เกม"** โดยผู้เชี่ยวชาญ (NodNuatTranslator) เมื่อนำมาใช้ร่วมกับโค้ด PUA วรรณยุกต์และสระจึงแสดงผลได้อย่างสมบูรณ์แบบ เนียนตา และไม่มีการทับซ้อนกันอีกเลย

## 3. สรุปแนวทางสำหรับเกมอื่นๆ (Best Practices)

หากคุณต้องทำ Mod เกม Unity (TextMeshPro) ในอนาคต ให้จำบทเรียนจาก Wasteland 3 ไว้ดังนี้:

1.  **Format สำคัญ:** การส่งไฟล์ให้ TStudio ต้องเป๊ะทั้งคอลัมน์ (`ID`, `Source`, `Translation`, `AI_Reference`) และ Encoding (`utf-8-sig`)
2.  **ใช้ PUA เสมอ:** ก่อนแพ็กข้อความเข้าเกม Unity ต้องแปลงข้อความภาษาไทยผ่าน PUA Engine ทุกครั้ง
3.  **การเลือกฟอนต์คือตัวตัดสิน:** อย่าคิดว่าฟอนต์ PUA ตัวไหนก็เหมือนกัน! หากพบปัญหาสระลอย/วรรณยุกต์จม แม้จะใช้ PUA แล้ว ให้สันนิษฐานไว้เลยว่าเป็นที่ "ระยะ (Metrics)" ของตัวฟอนต์เอง **จงเปลี่ยนไปใช้ฟอนต์ที่ถูก Modify มาสำหรับงาน Mod เกมโดยเฉพาะ** (เช่น ตระกูล fixByNodNuatTranslator) แทนที่จะใช้ฟอนต์มาตรฐานทั่วไป
4.  **C# IL2CPP Injection:** เป็นทางออกที่ทรงพลังที่สุดในการแทรกฟอนต์โดยไม่ต้องไปยุ่งกับไฟล์ Asset ภายในมากเกินไป
