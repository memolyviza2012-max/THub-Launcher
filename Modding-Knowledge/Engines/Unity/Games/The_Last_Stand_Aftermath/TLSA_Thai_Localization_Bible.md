## 🎯 1. Overview
The Last Stand: Aftermath is a Unity IL2CPP game. The text is stored inside Unity Addressables (`.bundle` files). Because of the complexities of IL2CPP and Addressables, the most robust translation method is:
1. **Dynamic Font Replacement**: Bypassing Unity's fragile OS font generator using Harmony hooks (inspired by the *Until We Die* methodology).
2. **Text Hooks**: Utilizing `XUnity.AutoTranslator` to intercept text at runtime (`TMP_Text.text` setter).
3. **Advanced Extraction**: A custom Python script (`UnityPy`) to extract all strings directly from Addressables bundles into TStudio CSV.
4. **TStudio Bridge**: Python scripts (Unpacker/Packer) to convert TStudio's CSV back into XUnity's `.txt` format while applying Thai Private Use Area (PUA) adjustments automatically.

## 🛠️ 2. The Engine Instability Problem (IL2CPP)
**The Problem:**
Initially, attempting to create an OS fallback font using standard reflection or `Il2CppInterop` (`Font.CreateDynamicFontFromOSFont`) resulted in severe TypeLoad exceptions and native crashes. The .NET JIT compiler struggles to map complex IL2CPP arrays (`Il2CppReferenceArray<string>`) required by the Font APIs.

**The Solution (The "Until We Die" Intercept Method):**
Instead of invoking the buggy native Unity APIs, we create a **Fake Font** and intercept the lower-level `FontEngine.LoadFontFace` method.
```csharp
// Fake Font Creation
var osFont = new Font("TLSAThaiFallback");
osFont.name = "TLSAThaiFallback";
var fa = TMP_FontAsset.CreateFontAsset(osFont);
```
By patching `UnityEngine.TextCore.LowLevel.FontEngine.LoadFontFace`, we redirect the request directly to the raw `.ttf` file on disk:
```csharp
[HarmonyPatch(typeof(FontEngine), "LoadFontFace", new Type[] { typeof(Font), typeof(int) })]
public class FontEngine_LoadFontFace_Patch1
{
    public static bool Prefix(Font font, int pointSize, ref FontEngineError __result)
    {
        if (font != null && font.name == "TLSAThaiFallback" && LiveTranslationMod.ThaiTtfPath != null)
        {
            // Bypass Unity completely, load from OS path
            __result = FontEngine.LoadFontFace(LiveTranslationMod.ThaiTtfPath, pointSize);
            return false; // Skip original
        }
        return true;
    }
}
```
This forces TextMeshPro to generate a valid `TMP_FontAsset` for our Thai `.ttf` without ever triggering the crash-prone OS Font conversion logic.

## 🔍 3. Text Extraction (Unity Addressables)
The game text is deeply embedded inside `TLSA_Data/StreamingAssets/aa/StandaloneWindows64/` (Unity Addressables), scattered across `MonoBehaviour` trees (dialogues, books, items) and `TextAsset` files.

Instead of writing a custom packer to rebuild these `.bundle` files (which is incredibly difficult), we use an **Advanced Extractor Script** based on `UnityPy`.
- It recursively scans Typetrees of `MonoBehaviour` objects across all `.bundle` files.
- It uses regex validation (`is_valid_text`) to filter out hashes, file paths, and internal variable names.
- It outputs exactly 5,186 valid translation strings directly to `TLSA_Translation.csv`.

## 🌉 4. Modder Hub (TStudio) Integration
Since we cannot (and should not) modify the core TStudio files, we created two standalone bridging scripts:

### A. TLSA_extractor_advanced.py (Unpack to CSV)
Runs a brute-force text extraction across the Addressables bundles and outputs to `02_Translation_Workspace\TLSA_Translation.csv`.

### B. TLSA_packer.py (Pack to XUnity)
Takes the translated `TLSA_Translation.csv` and generates `_AutoGeneratedTranslations.txt` or `TLSA_Translated.txt` for XUnity.AutoTranslator.
**CRITICAL FEATURE:** The packer includes a `convert_to_pua` function. It maps standard Thai vowels/tone marks to Private Use Area (PUA) characters specifically mapped in our custom Font Asset.
- Example: "ที่" -> "ท"
This ensures that the text fed to XUnity is already pre-formatted to bypass Unity's broken Thai rendering, without needing a heavy runtime regex processor on every text update.

## 🎮 5. XUnity Configuration
To tie everything together, XUnity AutoTranslator must be configured to use our injected font:
`Config.ini`
```ini
[Behaviour]
Language=th
FromLanguage=en
OverrideFontTextMeshPro=TLSA Thai Fallback SDF
```
Because the `TLSA_LiveTranslation.dll` successfully forces TextMeshPro to build `TLSA Thai Fallback SDF` at runtime, XUnity can find it and seamlessly apply it to all replaced texts.
