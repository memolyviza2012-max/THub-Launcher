# คัมภีร์แปลภาษาไทยเกม Little Goody Two Shoes (Unity / IL2CPP)
**เทคนิค: Live Dynamic Hooking (Unity UI TextMeshPro) & Synchronous CSV Writing**

คัมภีร์นี้บันทึกประวัติการสร้าง, ปัญหาที่พบ, และเทคนิคเชิงลึกทั้งหมดในการสร้าง "LGTS Live Translation Engine" ซึ่งเป็น BepInEx Plugin สำหรับแทรกภาษาไทยแบบ Real-time เข้าไปในเกม Unity ที่ไม่มีการจัดการระบบภาษาที่ง่ายพอให้ Modder แก้ไขไฟล์ตรงๆ (โดยเฉพาะกรณีที่เกมดึงข้อความจากโค้ดหรือฐานข้อมูลที่ถูก Compile ไปแล้ว)

## 🎯 1. แนวคิดและสถาปัตยกรรมหลัก (Architecture)

เนื่องจากตัวเกมอาจจะมีการดึงข้อความจากหลายแหล่ง และการแปลไฟล์ Raw Unity Asset อาจมีข้อจำกัดเรื่องโครงสร้างไฟล์ การแก้ปัญหาที่ทรงพลังที่สุดคือการ **ดักจับที่ปลายทาง (End-Point Hooking)**

**ระบบปลายทางของเกม Unity ในยุคใหม่ส่วนใหญ่คือ `TMPro.TMP_Text.text`**
เราจึงใช้ BepInEx + Harmony ในการเข้าไปฝังโค้ด (Patch) ที่ `MethodType.Setter` ของ Property `text` ในคลาส `TMP_Text` 

### สถาปัตยกรรม:
1. **The Plugin Core (`Plugin` class):**
   - รันตัวเองด้วย `BaseUnityPlugin` ทำหน้าที่ตอนเกมเปิด 
   - รับผิดชอบโหลดไฟล์ `LGTS_Master_Translation.csv` เข้าระบบ Memory
   - ตรวจสอบว่าผู้ใช้เซฟไฟล์ CSV หรือไม่ (หากมีการแก้ไข CSV นอกเกม เกมจะรู้ตัวและอัปเดตคำแปลใหม่ทันที โดยเช็คจาก `File.GetLastWriteTime` แบบทุกๆ 60 เฟรม)
2. **The Hook (`TMP_Text_Patch`):**
   - ดักจับการพยายามเปลี่ยนข้อความบนจอทุกครั้ง (`Prefix` & `Postfix`)
3. **The Enforcer (`LiveTranslationTracker`):**
   - ออบเจกต์พิเศษที่ฝัง (AddComponent) เข้าไปใน UI ของเกม เพื่อบังคับไม่ให้สคริปต์ของเกมเปลี่ยนข้อความแปลของเรากลับไปเป็นภาษาอังกฤษ

## 🛠️ 2. เทคนิคขั้นสูงและบทเรียนจากข้อผิดพลาด (Advanced Techniques & Post-Mortem)

ระหว่างการพัฒนา เราเจอปัญหาใหญ่หลายเรื่องที่ส่งผลให้ระบบพังหรือคำแปลไม่ยอมโชว์ นี่คือบทสรุปของปัญหาและ "เทคนิค" ที่ใช้แก้ไข

### ปัญหาที่ 1: เกมเปลี่ยนคำแปลกลับเป็นอังกฤษ (The Override Problem)
**อาการ:** ข้อความไทยกระพริบขึ้นมาเสี้ยววินาที แล้วกลับเป็นอังกฤษ
**สาเหตุ:** เกมมักจะมี "Typewriter Effect" (ตัวหนังสือค่อยๆ พิมพ์) หรือสคริปต์ Update ของเกมเองที่พยายามเขียนทับ (Overwrite) ข้อความของเราอย่างต่อเนื่อง
**เทคนิคการแก้ (The Enforcer Pattern):**
- ห้ามแก้แค่ตอน Hook `Prefix` อย่างเดียว! 
- ตอน Hook `Postfix` ให้แอบฝัง `LiveTranslationTracker : MonoBehaviour` ลงไปใน GameObject ของ UI ตัวนั้นเลย
- ให้ `tracker` จำค่า "ภาษาอังกฤษต้นฉบับ" เอาไว้
- ในลูป `Update()` ของ `tracker` มันจะคอยเฝ้าดูว่าถ้า `textComponent.text` ไม่ตรงกับคำแปลภาษาไทยของเรา มันจะ "ตบ" ให้กลับมาเป็นภาษาไทยซ้ำๆ แบบ 60 เฟรมต่อวินาที (Aggressive Enforcement)

### ปัญหาที่ 2: เครื่องมือจดบันทึกตายตอนเกมโหลดฉาก (The Coroutine Death)
**อาการ:** ข้อความภาษาอังกฤษใหม่ๆ ที่ขึ้นบนจอ ไม่ยอมถูกดึง (Dump) ลงไฟล์ CSV หลังจากเล่นเกมไปได้สักพัก
**สาเหตุ:** 
- ตอนแรกเราเขียนระบบดึงข้อความให้ส่งคิวไปหา "พนักงานจดบันทึก" ที่ทำงานด้วย `Coroutine` ใน Unity
- แต่พอเกมโหลดฉาก (Scene Transition) เกมอาจจะสั่ง Disable GameObject หรือมีสคริปต์บางอย่างไปตัดการทำงานของ Coroutine ทำให้พนักงานจดบันทึก **ตายถาวร**
**เทคนิคการแก้ (Synchronous Direct Write):**
- รื้อระบบคิว (Queue) ทิ้งทั้งหมด!
- เปลี่ยนมาใช้ระบบ **"เห็นปุ๊บ จดปั๊บ"** (Synchronous Direct Write) 
- เมื่อ Hook `Prefix` เจอประโยคอังกฤษใหม่ มันจะเปิดไฟล์ CSV และเขียนบรรทัดใหม่ด้วย `File.AppendAllText` ทันที ณ เสี้ยววินาทีนั้น โดยไม่ต้องรอคิวข้ามเฟรม! (I/O ของ Text file เล็กๆ นั้นเร็วมากจนไม่ทำให้เกมกระตุก)

### ปัญหาที่ 3: ไฟล์โดนล็อคจาก Excel (The UnauthorizedAccessException)
**อาการ:** คนแปลเปิดไฟล์ CSV ค้างไว้ใน Excel/TStudio เพื่อแก้คำแปล แล้วจู่ๆ ระบบดึงข้อความใหม่ของเกมก็พัง
**สาเหตุ:** เมื่อโปรแกรมอื่นเปิด CSV ค้างไว้ OS (Windows) จะล็อคไฟล์ไม่ให้ใครเขียนทับ (File Lock) ส่งผลให้คำสั่ง `File.AppendAllText` โยน Exception (`UnauthorizedAccessException`) ทำให้ลูปการทำงาน Crash แบบกู่ไม่กลับ
**เทคนิคการแก้ (Robust Exception Catching & Retries):**
- ใส่ `try ... catch (Exception)` ครอบคำสั่งเขียนไฟล์เสมอ
- **ไม้ตาย:** ถ้าเขียนไม่สำเร็จ (เพราะไฟล์ล็อคอยู่) ให้ลบข้อความนั้นออกจาก "ความจำชั่วคราว" (`sessionHookedTexts.Remove`) เพื่อที่ว่าครั้งหน้าที่ข้อความนี้ปรากฏบนจอ ระบบจะได้ "พยายามเขียนลงไฟล์ใหม่อีกครั้ง" (Retry Mechanism) แทนที่จะยอมแพ้ไปตลอดกาล

### ปัญหาที่ 4: ข้อมูลซ้ำซ้อนใน CSV (The Duplication Bug)
**อาการ:** ประโยคดั้งเดิมที่มีอยู่ในไฟล์ CSV แล้ว แต่ยังไม่ได้ถูกแปลเป็นไทย กลับถูกระบบ Hook ดึงมาต่อท้ายไฟล์ซ้ำๆ
**สาเหตุ:** 
- โค้ดเก่าบอกว่า: "ถ้าหาใน Dictionary แล้วเจอ ให้แปล ... ถ้าไม่เจอ ให้ดึงข้อความใหม่ลง CSV"
- โค้ดโหลด CSV (`LoadCSV`) ดันข้าม (Skip) การโหลดประโยคที่ไม่มีคำแปลลง Dictionary! ทำให้เวลาระบบค้นหาใน Dictionary มันจึง "ไม่เจอ" ประโยคนั้น และคิดว่าเป็นประโยคใหม่
**เทคนิคการแก้ (The Double-Layer Tracking):**
- ต้องสร้าง HashSet แยกต่างหาก (เช่น `knownCsvTexts`) 
- ตอนโหลด CSV ให้โยน "ภาษาอังกฤษต้นฉบับ" **ทุกประโยค** ลงไปใน `knownCsvTexts` ไม่ว่ามันจะมีคำแปลแล้วหรือไม่ก็ตาม
- ตอน Hook ให้เช็คว่า `if (!knownCsvTexts.Contains(text))` จึงจะทำการเขียนลงไฟล์ CSV
- วิธีนี้ทำให้ประโยคที่มีโครงสร้างอยู่แล้วในไฟล์ จะไม่มีวันโดนดูดซ้ำอีกเลย!

## 📋 3. คู่มือการจัดการไฟล์ (File Management)

1. **Master CSV (`LGTS_Master_Translation.csv`)**
   - รวบรวมทุกข้อความในเกม (ทั้งที่มาจากการดึงจาก Raw Asset และที่ดึงแบบสดๆ)
   - คอลัมน์ที่ใช้งานคือ: `ID`, `Source`, `Translation`, `Comments`
2. **การทำความสะอาด (CSV Cleaning)**
   - หากเจอข้อผิดพลาดจนเกิด Duplicate ID หรือ HOOK_ID ขึ้นมาซ้ำกับเนื้อหาที่อยู่ในเกม (เช่น `Cutscenes/CUT_1_5...`) 
   - สามารถเขียน C# Script ในการรวมร่างและลบบรรทัดที่ซ้ำกัน โดยยึดหลัก: 
     - "เก็บเวอร์ชันที่มีคำแปลไทยไว้เสมอ" 
     - "ให้ความสำคัญกับ Original ID มากกว่า HOOK_ID"

## 🚀 4. สรุป (Conclusion)

สถาปัตยกรรม **LGTS Live Translation Engine v2.0.7+** คือผลึกความรู้ของการทำ Live Translation ใน Unity:
- รวดเร็วและเสถียร ไม่พึ่งพา Coroutine 
- ป้องกันการ Overwrite ของเกมด้วย Enforcer Component ลูป Update ระดับ UI
- กันไฟล์บวมด้วย Double-Layer Tracking
- ล้มลุกคลุกคลานได้ (Resilient) แม้ไฟล์ CSV จะโดนล็อคด้วย External Editor ก็ตาม

เทคนิคนี้สามารถนำไปดัดแปลงใช้กับเกม Unity (IL2CPP / Mono) เกมไหนก็ได้บนโลกใบนี้ที่ใช้ TextMeshPro เป็นแกนหลัก!
